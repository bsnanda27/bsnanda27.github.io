PROJECT NOTES / 01
Digital hardware · Vision Transformers

TokenFold.

Selecting what matters.
Understanding the cost of moving it.

The idea

Vision Transformers represent an image as a sequence of tokens. TokenFold explores a hardware sidecar that selects tokens and compacts their embedding rows before downstream computation. Its aim is to reduce the work passed to later stages while accounting for the cost of selection and data movement.

Design focus

Selection & compaction

Translate reference behaviour into hardware, preserving selected rows and their original-token correspondence.

Streaming behaviour

Handle valid/ready transfers and backpressure so that accepted data remains consistent through the pipeline.

Control & data movement

Connect configuration, status and DMA behaviour with the hardware datapath.

Verification

Compare RTL behaviour with a software reference, then check the integrated data path in system simulation.

The engineering question

Fewer tokens do not automatically mean a faster system. The benefit must outweigh selection and transfer overhead. Functional correctness and end-to-end performance are separate questions; full-model speedup and accuracy preservation are not claimed here.

What this project brings together

RTL design, software-reference modelling, handshake debugging, hardware/software integration and careful interpretation of benchmark results.

PROJECT NOTES / 02
Processor architecture · RTL to synthesis

RV32I processor.

An architecture on paper.
A processor in logic.

The project

A from-scratch processor design targeting the RISC-V RV32I instruction set, with a scope spanning RTL development, simulation and synthesis. It connects instruction-level behaviour with the logic needed to execute a program.

Reading the architecture

RV32I is the base 32-bit integer instruction set of RISC-V. Its architectural behaviour includes arithmetic and logic, loads and stores, branches and jumps. A processor implementation translates these instructions into control signals and data movement.

Design considerations

Datapath & control

How register values, immediate operands, arithmetic logic and control decisions work together.

Program flow

How instructions determine the next program-counter value, including branch and jump behaviour.

Simulation & debugging

How instruction behaviour can be checked in testbenches and traced through waveforms.

Synthesis & timing

How RTL becomes a logic netlist, and how synthesis reports connect design choices with implementation constraints.

What this project connects

Computer architecture, RTL design, waveform-based debugging and the transition from behavioural design to synthesized logic.
